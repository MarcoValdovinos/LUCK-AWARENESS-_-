# RFC 0001: Protocolo de Co-Creatividad Simbiótica (Borrador 0.1)

## 1. Estado del Documento
- **Estado:** Borrador (Draft)
- **Versión:** 0.1.0
- **Autor:** Marco Antonio Rojas Valdovinos
- **Fecha:** Noviembre 2026

## 2. Objetivo
Proveer un formato interoperable para registrar la procedencia de obras creadas con participación humana e IA, sin imponer modelos legales de autoría. El protocolo busca que un tercero pueda verificar **quién declaró qué, en qué versión y si los bytes han sido alterados**.

## 3. Principios de Diseño
1. **Separación de conceptos:** Un hash prueba integridad, no autoría. Una firma vincula una clave, no una identidad legal.
2. **Consentimiento explícito:** No se registran aportes humanos sin un campo booleano de consentimiento.
3. **Privacidad por defecto:** No se almacenan *prompts* completos ni datos personales identificables (PII) en el manifiesto público.
4. **Corregibilidad:** El historial no se borra; se añaden eventos de revocación o disputa.

## 4. Estructura del Registro (Manifiesto)
El registro se serializa en JSON y cumple con el esquema `manifest.schema.json`. Incluye:
- Metadatos de la obra (ID, versión, hash).
- Declaración de contribuciones (Humano, Modelo IA, Agente).
- Firmas digitales opcionales.
- Campo obligatorio de limitaciones.

## 5. Proceso de Verificación
Cualquier implementación compatible debe poder:
1. Validar el JSON contra el esquema.
2. Recalcular el hash del contenido original y compararlo con el campo `content_hash`.
3. Listar las contribuciones declaradas.

## 6. Fuera del Alcance (Limitaciones)
Este protocolo **no** resuelve:
- Disputas legales de propiedad intelectual.
- La veracidad de la declaración (si alguien miente, el protocolo solo registra que mintió).
- La identidad legal de quien firma (solo vincula una clave criptográfica).
